# Резервные Копии

Сохраняй базу, Supabase Auth, закрытые Storage buckets, `content/live`, `content/media`, бренд и версии кода. Секреты сохраняй отдельно в зашифрованном хранилище. ZIP шаблона не содержит рабочих аккаунтов и не является резервной копией установки.

Используй резервное копирование своего тарифа Supabase и проверяй восстановление в отдельном закрытом проекте. Не меняй UUID Auth при переносе: к нему привязаны история, identities, заказы и подписка. Не смешивай данные двух клиентов и не пересчитывай сроки по email.

Восстановленный проект получает свои URL/ключи; installationId должен соответствовать восстановленной базе. Пока сверка платежей не завершена, оставь billing выключенным. Проверь RLS двумя аккаунтами, доступ после истечения, owner фотографий, обработку повторной оплаты и работу своего webhook. Историю применённых миграций сохраняй вместе с backup.

При обновлении сначала сделай backup, проверь новую версию в отдельной среде, применяй только новые forward-миграции. Не заменяй каталог приложения целиком архивом поверх рабочей папки с env и контентом. Откат кода не откатывает пользовательские данные автоматически.
