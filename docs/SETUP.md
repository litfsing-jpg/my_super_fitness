# Установка

1. Распакуй проверенный ZIP в отдельную папку. Установи Node 22+ и выполни `npm ci`, затем `npm run demo`. Не используй чужие env, базы, ботов и домены.
2. Создай новый Supabase-проект только для этой платформы. Примени `backend/migrations/*.sql` строго по порядку через SQL Editor или свою migration-систему. Первая миграция откажется работать поверх уже существующего приложения. Не изменяй применённые миграции: добавляй следующие.
3. Получи UUID: `select id from public.wl_installation;`. Это `WL_INSTALLATION_ID`, а не случайный ID из другой установки.
4. Выполни `npm run setup -- --mode hybrid --origin https://your-domain.example`. В `.env.local` укажи URL/anon/service ключи собственного проекта. Service key хранится только на сервере. Файл не коммить и не пересылай ученикам вместе с шаблоном.
5. Настрой собственный SMTP, подтверждение email, Site URL и разрешённый callback `https://your-domain.example/login` в Supabase Auth. Для привязки email к Telegram-аккаунту отключи двойное подтверждение смены email (`Secure email change`): новый адрес всё равно подтверждается письмом. Не отключай подтверждение регистрации. Подробности в `AUTH.md`.
6. Замени `client/legal/offer.html`, `privacy.html`, `consent.html` своими проверенными документами. Укажи поддержку в `brand.config.json`. Задай одинаковую ревизию в env и БД: `update public.wl_installation set legal_ready=true, legal_revision='your-revision', legal_docs='{"offer":"/legal/offer.html","privacy":"/legal/privacy.html","consent":"/legal/consent.html","health":"/legal/consent.html"}'::jsonb;`. Только после проверки документов включай `WL_LEGAL_READY=1`. Новая ревизия требует нового согласия до чтения платных данных, включая прямые запросы к базе и Storage.
7. В режимах `telegram`/`hybrid` создай своего бота через BotFather. Укажи его token, username без `@`, случайный webhook secret от 32 символов. Разреши собственный HTTPS-домен Mini App. Webhook регистрируется владельцем отдельно на `/api/bot/webhook` с тем же `secret_token`; запуск сервера этого не делает. Меню Mini App тоже задаётся в своём BotFather/API.
8. Подготовь `content/live` и `content/media` по `CONTENT.md`. Для первого локального показа уже есть `content/demo`; в production он автоматически не подключается. Добавь собственные тарифы и настрой оплату по `PAYMENTS.md`.
9. Выполни `npm run doctor`, исправь ошибки. Офлайн-проверка не доказывает доступность SMTP/бота/магазина. Проверь тестовый signup, подтверждение письма, оба входа, привязку, отсутствие двойной подписки и тестовую оплату на своих подключениях.
10. Основной выпуск: `docker compose -f deployment/compose.yaml build`, затем `docker compose -f deployment/compose.yaml up -d`. Нужны HTTPS `WL_APP_ORIGIN`, writable `content/live` для пользователя Node UID 1000 и HTTPS-прокси по примеру Caddyfile. Все маршруты проходят через Node; не раздавай папку проекта или `/assets` отдельным публичным static-сервером.

Первый администратор назначается только после создания своего аккаунта: `npm run admin -- --user UUID --confirm`. Команда обращается к указанной в собственном env базе и проверяет installationId. Автоматического назначения по email нет. Панель: `/manage`; ограниченный импорт JSON до 32 КБ за запрос. Большие каталоги размещай как проверенные файлы на сервере.

Чистый шаблон преднамеренно не готов к приёму денег до настройки владельцем. Не включай live-режим до проверки документов, чеков, поддержки, callback и резервного копирования.
