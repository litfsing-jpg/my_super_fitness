# Оплата

Web использует собственный магазин YooKassa, Telegram digital access использует Stars. Это два адаптера над одним серверным заказом и общей подпиской. RUB и XTR учитываются отдельно; Stars не являются рублями. Тариф по умолчанию выключен. Автосписаний нет.

Задай цены в `wl_billing_plans`: `amount_minor` в копейках RUB, `stars_amount` целое число Stars, `days` срок. Менять тарифы может назначенный сервером администратор. Цена и UUID из браузера не являются доказательством оплаты.

Для Web нужны собственные `WL_YOOKASSA_SHOP_ID`, `WL_YOOKASSA_SECRET`, `WL_BILLING_ENABLED=1`. Сначала `WL_BILLING_MODE=test` с тестовым магазином; в live сервер ожидает `test:false`. Если бизнесу требуется чек, настрой его отправку со своим магазином и кассой до live. Готового юридического заключения или универсальной фискализации в шаблоне нет; checkout нельзя считать готовым без проверки этих условий.

Webhook YooKassa: `/api/billing/webhook/yookassa`. Уведомление само по себе не выдаёт доступ: сервер получает платёж через provider GET и сверяет shop, сумму, валюту, test flag, metadata заказа и владельца. Redirect из браузера не подтверждает покупку. Provider POST использует ID сохранённого заказа как idempotency key. После 23 часов неопределённый create не повторяется: заказ требует ручной сверки, чтобы не создать второе списание после 24-часового окна.

Для Mini App включи `WL_STARS_ENABLED=1`. Test использует отдельную тестовую среду Telegram (`/test/` API, тестовый бот/аккаунт); production-бот и test flag не взаимозаменяемы. Invoice содержит UUID заказа, валюту XTR и серверную цену. Pre-checkout сверяет реальную Telegram identity и резервирует одну оплату заказа. Только trusted successful_payment или проверенная Star transaction выдаёт доступ. UI callback ничего не начисляет.

Повтор webhook/проверки не добавляет второй период. Продление начинается от `max(now, currentExpiry)`. Прогресс не удаляется. Полный возврат последней покупки убирает только неиспользованное продление; старые и частичные возвраты переводятся на ручную сверку, чтобы не отозвать другую уже оплаченную подписку. Stars refund проходит через trusted bot update. Сверка Star transactions ограничена последними 1000 событиями; более старые пропуски разбирает оператор.

Worker повторяет проверки сохранённых pending-заказов раз в минуту. Повтор после неизвестного результата использует тот же заказ. Владелец должен следить за review-заказами, webhook и сверять расчётный реестр со своим провайдером. Тесты шаблона используют fake-провайдеры и одноразовую SQL/Auth; реальный магазин и деньги в ходе сборки не задействованы.

Контракты: [YooKassa API](https://yookassa.ru/developers/api), [идемпотентность](https://yookassa.ru/developers/using-api/interaction-format), [Telegram Stars](https://core.telegram.org/bots/payments-stars), [Bot API](https://core.telegram.org/bots/api).
