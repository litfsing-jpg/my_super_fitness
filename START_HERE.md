# Начни Здесь: Установка Своей Фитнес-Платформы

В этой папке весь шаблон: приложение, сервер, база в виде миграций, демо-контент, тесты и инструкции. Ничего из соседних проектов не требуется. Рабочие базы, участники, ключи и видео автора сюда не входят.

Есть два разных сценария:

- **Посмотреть интерфейс:** локальное демо, без базы, Telegram и оплаты.
- **Запустить свою платформу:** собственные Supabase, документы, домен и подключения. Подключения автора использовать нельзя.

## 1. Быстрый Просмотр На Компьютере

Нужен Node.js 22 или новее вместе с npm. В терминале открой эту папку, где находится `package.json`.

```sh
node --version
npm ci
npm run demo
```

Открой [локальное демо](http://127.0.0.1:4211/). Остановка: Ctrl+C в терминале сервера.

Если порт уже занят:

```sh
npm run demo -- 4212
```

Тогда адрес: http://127.0.0.1:4212/.

В демо есть анкета, тренировка с подходами, питание, вода, прогресс и два рецепта с анимацией. Видео помечены как демонстрационные: это иллюстрации плеера, не уроки тренера. Серверные записи демо хранятся в памяти и исчезают после остановки. Настоящих участников в демо не добавляй.

## 2. Выбери Режим Своей Установки

| Режим | Что Получится |
| --- | --- |
| `web` | Самостоятельный сайт, вход по email, без зависимости от Telegram |
| `telegram` | Telegram Mini App с входом через своего бота |
| `hybrid` | Оба входа в одну платформу с общей подпиской и прогрессом после явной привязки |

Для обоих каналов используй `hybrid`. Для обычного сайта без Telegram выбери `web`: бот в этом режиме не нужен. Два уже созданных аккаунта автоматически не объединяются.

## 3. Подготовь Собственные Сервисы

Для рабочей установки нужны:

- Новый отдельный проект Supabase: Auth, PostgreSQL и приватный Storage.
- Свой HTTPS-домен и сервер с Docker Compose; внешний HTTPS-прокси, например Caddy по приложенному примеру.
- Свой SMTP для писем входа и подтверждения адреса, если используется email.
- Собственный Telegram-бот для `telegram` или `hybrid`.
- Свой магазин YooKassa для оплаты на сайте; Telegram Stars для покупки внутри Mini App. Цены настраиваются отдельно.
- Свои документы, адрес поддержки, упражнения с видео и каталог питания.

Не применяй миграции к существующей клиентской базе. Развёртывание на сервере, создание облачных ресурсов и реальные оплаты выполняет владелец с отдельным подтверждением. Эти действия инструкция сама не запускает.

## 4. Создай Чистую Базу

В SQL Editor нового Supabase-проекта выполни файлы полностью, по одному и строго в таком порядке:

```text
backend/migrations/001_access.sql
backend/migrations/002_app.sql
backend/migrations/003_runtime_rls.sql
backend/migrations/004_identities.sql
backend/migrations/005_billing.sql
backend/migrations/006_stars.sql
backend/migrations/007_review_guards.sql
backend/migrations/008_proofs.sql
```

Даже в режиме `web` применяется весь этот набор. После каждого файла проверь успешное выполнение; при ошибке не продолжай и не пытайся снять защитные проверки. Применённые миграции не переписывай.

Затем выполни:

```sql
select id from public.wl_installation;
```

Сохрани полученный UUID: это `WL_INSTALLATION_ID` именно этой базы.

## 5. Создай Конфигурацию

Команда выполняется из корня проекта. Замени пример домена своим адресом и при необходимости измени режим:

```sh
npm run setup -- --mode hybrid --origin https://your-domain.example
```

Появится `.env.local` с пустыми настройками. Команда ничего не регистрирует в облаке и не перезаписывает существующий `.env.local`. Если файл уже есть, открой его и отредактируй вручную, не удаляй рабочие значения ради повторного setup.

Заполни в `.env.local`:

| Переменная | Значение |
| --- | --- |
| `WL_MODE` | `web`, `telegram` или `hybrid` |
| `WL_APP_ORIGIN` | Свой HTTPS-адрес, без пути, query и завершающего маршрута |
| `WL_INSTALLATION_ID` | UUID из предыдущего шага |
| `WL_SUPABASE_URL` | URL нового Supabase-проекта |
| `WL_SUPABASE_ANON_KEY` | Публичный publishable/anon ключ своего проекта |
| `WL_SUPABASE_SERVICE_KEY` | Серверный service-role/secret ключ своего проекта |
| `WL_BOT_TOKEN` | Свой токен бота, кроме режима `web` |
| `WL_BOT_USERNAME` | Имя своего бота без `@`, кроме режима `web` |
| `WL_BOT_WEBHOOK_SECRET` | Случайный секрет, минимум 32 символа, кроме режима `web` |

Остальные значения сначала оставь тестовыми: `WL_BILLING_ENABLED=0`, `WL_BILLING_MODE=test`, `WL_STARS_ENABLED=0`, `WL_LEGAL_READY=0`. Не подставляй вымышленные ключи, чтобы заставить doctor пройти.

`.env.local` содержит секреты. Не публикуй его, не добавляй в Git и не передавай вместе с шаблоном другим ученикам. Серверный ключ нельзя вставлять в HTML, браузерный JS или публичный бренд-конфиг.

## 6. Настрой Бренд, Вход И Документы

В `brand.config.json` измени название, короткое название, цвета, логотип и `supportEmail`. Поля и допустимые пути описаны в [BRANDING](docs/BRANDING.md).

В Supabase Auth укажи свой Site URL, разрешённый callback `https://your-domain.example/login` и SMTP. Проверь письмо подтверждения и восстановление входа. Подтверждение регистрации оставь включённым. Для добавления email к Telegram-аккаунту есть отдельные требования к подтверждению смены адреса: следуй [AUTH](docs/AUTH.md), не отключай подтверждения целиком.

Замени собственными проверенными текстами:

```text
client/legal/offer.html
client/legal/privacy.html
client/legal/consent.html
```

Удалять маркер-заглушку без настоящего документа нельзя. После проверки документов выполни в своей базе, заменив `owner-v1` своей версией:

```sql
update public.wl_installation
set legal_ready = true,
    legal_revision = 'owner-v1',
    legal_docs = '{"offer":"/legal/offer.html","privacy":"/legal/privacy.html","consent":"/legal/consent.html","health":"/legal/consent.html"}'::jsonb;
```

В `.env.local` поставь ту же версию:

```dotenv
WL_LEGAL_READY=1
WL_LEGAL_REVISION=owner-v1
```

До готовности документов не включай эти флаги. При изменении версии пользователю потребуется новое согласие.

## 7. Добавь Свои Упражнения И Рецепты

Рабочие JSON-каталоги размести в `content/live/`, свои видео и фотографии в `content/media/`. Эти каталоги создай до запуска Docker и настрой права: контейнеру с UID 1000 нужна запись в `content/live` и чтение приватных медиа.

Примеры форматов находятся в `content/examples/`, небольшой нейтральный набор в `content/demo/`. Для технического первого показа на своей тестовой установке можно явно скопировать нейтральные JSON из `content/demo` в `content/live`; автоматически в рабочий режим они не подключаются. Перед запуском участников замени примеры своим полноценным каталогом.

Видео указывай как `/api/media/your-video.mp4`. Приватные материалы не переноси в публичный `assets/neutral`. Для разнообразного меню двух демонстрационных рецептов недостаточно. Схемы каталогов, граммовки, КБЖУ и послойная графика: [CONTENT](docs/CONTENT.md).

## 8. Настрой Бота И Тестовую Оплату

Для `telegram`/`hybrid` создай своего бота в BotFather, укажи свой HTTPS-адрес Mini App. Отдельно зарегистрируй webhook на `https://your-domain.example/api/bot/webhook` с `secret_token`, равным `WL_BOT_WEBHOOK_SECRET`. Старт сервера webhook не регистрирует. Не меняй настройки существующего бота автора. В `web` этот шаг пропускается.

Для оплаты на сайте заполни собственные тестовые `WL_YOOKASSA_SHOP_ID`, `WL_YOOKASSA_SECRET`, затем включи `WL_BILLING_ENABLED=1`. Адрес уведомления магазина: `https://your-domain.example/api/billing/webhook/yookassa`.

Для Stars нужны собственные Telegram-подключения и `WL_STARS_ENABLED=1` вместе с включённым billing. Режим `test` использует тестовую среду Telegram, а не обычного production-бота.

Тарифы находятся в `wl_billing_plans`: `amount_minor` в копейках, `stars_amount` в Stars, `days` в днях. Тарифы в шаблоне выключены; задай свои цены и явно включи нужные. Автосписаний в шаблоне нет. Продление сохраняет тот же аккаунт и прогресс; внутри Telegram не подменяй Stars рублёвым checkout.

До live проверь свою тестовую покупку, выдачу доступа один раз, продление, возврат, поддержку и необходимые чеки. Детали и ограничения: [PAYMENTS](docs/PAYMENTS.md). Проверки шаблона не являются проверкой твоего магазина.

## 9. Проверь И Запусти На Сервере

Из корня проекта:

```sh
npm run doctor
```

Исправь каждую ошибку. В нетронутом шаблоне код выхода 1 нормален: собственных ключей, документов и поддержки ещё нет. Doctor проверяет локальную конфигурацию, но не доступность магазина, почты и бота.

После настройки своего сервера и домена:

```sh
docker compose -f deployment/compose.yaml build
docker compose -f deployment/compose.yaml up -d
docker compose -f deployment/compose.yaml logs --tail=100 app
```

Compose публикует Node только на `127.0.0.1:4210` сервера. Настрой HTTPS-прокси по `deployment/Caddyfile.example`, заменив домен своим. Все маршруты должны идти через Node. Не раздавай папку проекта, env, `content/media` или каталог базы отдельным static-сервером. Простая загрузка HTML на статический хостинг не заменяет этот сервер.

Открой свой HTTPS-адрес. Проверь `/health`, регистрацию, письмо, анкету и доступ после тестовой оплаты. Для локальной диагностики вместо Docker есть `npm start`; это не замена HTTPS-развёртыванию.

## 10. Назначь Своего Администратора

Сначала зарегистрируй и подтверди свой аккаунт. Узнай его UUID в собственном Supabase Auth. На доверенном компьютере или сервере с конфигурацией именно этой установки:

```sh
npm run admin -- --user YOUR_AUTH_USER_UUID --confirm
```

Замени `YOUR_AUTH_USER_UUID` настоящим UUID своего аккаунта. Команда меняет права в подключённой базе, поэтому внимательно проверь установку до запуска. Панель администратора: `/manage`. Совпадение email с каким-либо конфигом роль само не выдаёт.

## Перед Первым Участником

- Проверь Web и/или свой Mini App на физических Android и iPhone: клавиатура, кнопки, возврат, видео.
- Проверь сохранение подходов, еды, воды, рецептов и прогресса после повторного входа.
- Проверь, что чужой аккаунт не видит данные первого; без подписки платный контент закрыт.
- Проверь оба способа входа и явную привязку, если используется `hybrid`.
- Проверь тестовую оплату/возврат, текущие согласия, поддержку и резервное восстановление.
- Только затем отдельно принимай решение о live-платежах и запуске. См. [BACKUP](docs/BACKUP.md) и [LIMITATIONS](docs/LIMITATIONS.md).

## Как Передать Следующему Ученику

В выдаваемой папке `dist/` содержит чистый ZIP с этой инструкцией и manifest. После отдельной распаковки ZIP каталога `dist/` может не быть: он создаётся при новой сборке и не вкладывается сам в себя. Передавай ZIP, а не настроенную папку со своим `.env.local` и материалами участников. У каждого ученика отдельная база и подключения.

Для новой версии после своих изменений:

```sh
npm run package -- dist/fitness-whitelabel-next.zip
npm run verify:package -- dist/fitness-whitelabel-next.zip
```

Существующий архив не перезаписывается. Ключи, локальные зависимости и рабочий контент упаковщик исключает; неизвестные файлы и секретоподобные значения требуют проверки.

Для передачи работы агенту используй [HANDOFF](docs/HANDOFF.md). Структура: `client` — интерфейс, `server` — gateway/Auth/оплата/бот, `backend` — миграции, `content` — каталоги, `assets` — публичные демо-ресурсы, `deployment` — Docker/HTTPS, `tests` — проверки, `docs` — подробные инструкции.
